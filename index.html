For Course Instructors

Editing LMS Pages
Without Breaking Them

Our course pages all share the same simple structure and a small set of styles. You don't need to write HTML. You need to read the good version, recognise what changed when a page looks wrong, and put it back. This guide teaches exactly that — with a live editor you can experiment in.

Nothing you do on this page can affect a real course. Break things freely and watch what happens.
Part 1

The three ideas that explain everything

Ninety percent of "why does this page look wrong?" comes down to three small ideas. Read these, then take the quick check at the end.

1. A tag is a label wrapped around content

HTML is just your text with tags around it that say what each piece is. Most tags come in pairs — an opening tag and a closing tag — with your content in between:

<p>This is a paragraph.</p>
<strong>This is bold.</strong>

The closing tag has a slash: </p>. A few tags stand alone and close themselves — they end with /> and wrap nothing:

<br />        a line break
<img src="diagram.svg" />   an image

2. An attribute is extra info inside a tag

Inside the opening tag you'll see attributes — they look like name="value". The four you'll meet most:

  • class="examtip" and id="container" — names the styling looks for (more on this next).
  • src="diagram.svg" — where an image or video lives.
  • style="..." — styling written directly on the element. This one is the usual troublemaker.

3. The styling lives somewhere you never see

Here's the key one. The colours, fonts, boxes, and spacing are not on your page. They live in a separate company stylesheet (CSS) that you don't edit. That stylesheet says things like "anything with class="examtip" gets a light-blue box."

Your page simply has to use the right names in the right structure so the stylesheet can find each piece and dress it. That gives us the mental model for this whole guide:

You edit this

Structure + Names

The <div> wrappers and the class / id names on your page.

→
Triggers

A match

The stylesheet finds each name and applies the look meant for it.

→
You never edit this

The Styling

Fonts, colours, the blue tip box, the bordered container — all defined elsewhere.

So the two ways a page breaks are: (1) you remove or rename a wrapper/name, so the stylesheet can't find it — the styling silently falls off; or (2) a pasted style="..." overrides the stylesheet and fights the page's normal look. Everything in Part 4 is one of these two.

Quick check

Click each question to reveal the answer. If one surprises you, re-read the idea above it.

Is <br /> a tag?

Yes — it's a self-closing tag (it ends in /> and wraps no content). It just inserts a line break.

What does class="tipbox" actually do on its own?

By itself, nothing visible. It's a name the stylesheet looks for. The stylesheet says "style anything named tipbox like this." Rename it or remove it and the styling can no longer find that element.

Where is the light-blue colour of the Exam Tip box defined?

Not on the page you edit — in the company stylesheet (the .examtip rule). Your page only needs class="examtip" in the right place to switch it on.

You need to fix a typo in a sentence. What's safe to change — the words, or the <div> around them?

Only the words — the text between the tags. Leave the <div>, <p>, class names, and ids exactly as they are.

4
A class name got mistyped

      

        
The Exam Tip box's class was changed from examtip to
        exam-tip (an added hyphen):

        Broken
        

        

          
Broken — rendered

          
Fixed — rendered

        

        

        
What's wrong, and how do I fix it?
          

            
What's wrong: the stylesheet only knows the exact name
            examtip. exam-tip is a different name to it,
            so it matches nothing — the blue box vanishes and the tip shows as plain text.

            
What you'll notice: a box that used to have a colour/background is suddenly just
            bare text. Names must match character for character — no extra hyphens, spaces, or
            capital letters.

            
Related trap: swapping it to a real but different name changes the look
            instead of removing it — e.g. class="practitioner" turns the box
            green. The class name chooses which box you get.

Keep this handy

    
The safe-editing cheat sheet

    

      

        
Safe to do

        
    
          
  • Edit the words between tags — fix typos, reword sentences.
    • 
          
  • Add a new bullet by copying an existing <li>...</li> line.
    • 
          
  • Paste text using paste-without-formatting (Ctrl/Cmd + Shift + V).
    • 
          
  • Compare a broken page against the healthy shape in Part 2.
    • 
        

      

      

        
Handle with care

        
    
          
  • Never delete a <div> or its closing </div>.
    • 
          
  • Keep class and id names exactly as they are.
    • 
          
  • If pasted text looks "off", check for a stray style="..." and delete it…
    • 
          
  • …but leave the image-centring and video style="..." alone.
    • 
        

      

    

    
Before you save, ask: Does every box/heading still look like Part 2?
    Did I only change words? Do my <div> tags still balance? Any
    style="..." I didn't mean to add? If a page still looks wrong and you can't
    spot why, that's fine — flag it rather than guess.
